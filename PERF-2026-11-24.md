# Mesures de performance — 24 novembre 2026

## Méthode

- Banc : `scripts/bench.mjs` (Playwright, Chromium 158.0.8127.18 à part, `--use-angle=metal --enable-gpu
  --ignore-gpu-blocklist --mute-audio`), sans tête, GPU Metal réel (`ANGLE Metal Renderer: Apple M5`).
- Fenêtre 1440 × 900 à 2× (écran Retina), site construit (`npm run build`) servi par `vite preview` (port 4181),
  cache désactivé, adresses en `?muet`.
- Durée d'une image : chaque rappel `requestAnimationFrame` est chronométré, puis un `readPixels` d'un pixel est fait sur
  chaque contexte WebGL qui a dessiné : la mesure attend la fin réelle du travail GPU (`gl.finish()` n'attend pas sous
  Metal, les minuteurs GPU y sont faux). « Image lente » = plus de 20 ms.
- Coût de chaque effet : le même parcours est rejoué en coupant un effet à la fois (appel de dessin sauté dans le
  contexte visé, ou règle CSS neutralisée) ; médiane de 3 passages.
- Parcours accueil : chargement → fin de l'intro, 3 s immobile sur l'accueil, défilement à la molette (70 × 120 px),
  survol des vignettes, puis interactions (thème ×2, ouverture d'une fiche, défilement dans la fiche, Échap).
- Fiches : ouverture directe `?muet#p-<slug>` puis défilement dans la fiche.
- Profils processeur (`BENCH_PROFILE=dossier`) lus par `scripts/profile-top.mjs`.
- Résultats bruts : `work/2026-11-24/bench-avant.json` (avant), `work/2026-11-24/etape*.json` (après chaque étape).

### Durée d'une image (GPU compris), accueil, médiane de 3 passages

| Variante | Immobile p50 | Défilement p50 / p95 | Images lentes (défilement) | Survol vignettes p50 |
|---|---|---|---|---|
| Tout actif | 11,7 ms | 13,0 / 33,1 ms | 34 | 9,5 ms |
| Sans fond animé (`bg-canvas`) | 3,4 ms | 5,2 / 19,2 ms | 9 | 0,3 ms |
| Sans copies 2D du fond (bande haute, barre) | 11,9 ms | 12,8 / 34,0 ms | 23 | 6,0 ms |
| Sans passe verre des vignettes | 9,7 ms | 12,2 / 36,6 ms | 20 | 13,0 ms |
| Sans trame (halftone : vignettes, logo) | 8,6 ms | 11,4 / 33,3 ms | 16 | 12,3 ms |
| Sans tracé du nom (`name-trace`) | 9,4 ms | 11,5 / 27,0 ms | 18 | 9,7 ms |
| Sans flous CSS des mots (`.w` filter: blur) | 9,8 ms | 10,3 / 20,3 ms | **5** | 8,0 ms |
| Sans backdrop-filter (barre, bandes) | 9,5 ms | 11,1 / 20,2 ms | 8 | 6,1 ms |

Lecture :
- **Le fond animé est l'effet le plus cher : ~8 ms par image** sur 16,7 ms de budget, à chaque image, même immobile
  (il dérive en continu : jamais deux images identiques). Il force aussi le recalcul de tous les flous posés dessus
  (barre du haut, bandes).
- **Les flous des mots non allumés** (`filter: blur(2.5px)` sur ~200 mots) sont la première cause des saccades au
  défilement : 34 → 5 images lentes sans eux. Ils changent l'image : proposition seulement.
- Les flous de fond CSS (barre à 5 couches jusqu'à 16 px, bandes) : 34 → 8 images lentes. Idem, proposition seulement.
- Le processeur n'est pas le goulot : 0,4 ms par image immobile, 1,2 ms au défilement (profils). Tout le coût est GPU.
- Fiches ouvertes : 12,4 à 14,5 ms par image (p50), alors que la fiche est opaque et recouvre tout : le fond animé
  continuait d'être dessiné dessous.

## Problèmes repérés (lecture du code)

### Erreurs et fuites
- `main.js` `heroBgGo` : chaque `play()` refusé ajoutait un nouveau jeu d'écouteurs (`canplay`, `pointerdown`,
  `keydown`) sans retirer le précédent. **Corrigé (étape 1).**
- Aucun traitement de la perte du contexte WebGL (`webglcontextlost`) : écran figé ou vide si le GPU est réinitialisé.
- `backdrop.js` `readTheme` et `gl.js` `themeRGB` créent une toile 2D à chaque appel.
- Écouteurs `pointermove` globaux par fiche et par piste (jamais retirés ; pas une fuite, mais du travail inutile).
- `name-trace.js` : un MutationObserver sur `class` de `<html>`, qui change à chaque défilement (`cta-idle-off`) →
  `getComputedStyle` à chaque fois ; `main.js` ajoute `cta-idle-off` à chaque évènement de défilement.
- `gl.js` `levels()` utilise `OffscreenCanvas` (absent des anciens Safari).

### Code mort
- `gl.js` : seconde branche `uHasMask` de la trame (inatteignable), échantillonneur `uMask` inutilisé, `suck` toujours
  nul (la ligne d'halation ne fait rien), `GLASS_GLSL` injecté mais inutilisé, `uGlass`/`uBg` en partie inutilisés.
- `glass.js` : `insideDistance` inutilisée. `main.js` : `themeOf(b)` ignore son paramètre.
- `logo-tune-panel.js`, `iris-debug.js` : outils de réglage, chargés seulement en développement.

### Calculs refaits à chaque image
- `gl.js` : `getBoundingClientRect` sur ~60 vues (vignettes + 4 copies de chaque piste), deux fois par image, plus les
  rectangles de découpe et `elementFromPoint`.
- `main.js` `scrollEffects` : rectangles du pied de page et des blocs de mots lus à chaque image, même immobile.
- `F.frame` réécrit la transformation de la rangée de fiches à chaque image sans test de changement.
- `updateFlow` reconstruit la table de 512 couleurs à chaque image dès que le logo ou la lentille est visible
  (voulu : la roue « flux » s'anime).
- La vue du gros logo couvre toute la toile (~5 Mpx à 2×) à chaque image.

### CSS coûteux
- `filter: blur()` sur chaque mot non allumé (~200), `backdrop-filter` empilés (barre : 5 couches, bandes, fiches),
  animation `curtain-in` sur une propriété personnalisée (`--cut`, recalcul de style à chaque image).

### Fichiers trop gros
- `gl.js` 90 Ko / 1 201 lignes, `main.js` 64 Ko / 953 lignes, `styles.css` 85 Ko.

### Chargement
- Vidéo HLS : voir plus haut (81 Mo).
- Cache : GitHub Pages envoie `max-age=600` même pour les fichiers versionnés de `/assets/`.
- Images des vignettes : WebP 20 à 292 Ko, sans `srcset` ; image de l'accueil `riviere-calme.webp` sans dimensions.
- Polices : 123 Ko, déjà préchargées.

### Solidité, accessibilité
- Pas de repli si le contexte WebGL est perdu ; le repli sans WebGL existe (classe `has-gl` absente : images DOM).
- `.work__track:focus-visible { outline: none; }` : la piste focalisable au clavier n'a aucun focus visible.
- En-têtes de sécurité autrefois dans `vercel.json` (X-Frame-Options, Permissions-Policy, COOP) plus envoyés.
- `npm audit` : 0 vulnérabilité. Console : aucune erreur (FR, EN, mentions légales, holosene, mobile 390 × 844).

## Restes (pas faits, faible gain ou risque)

- Code mort dans les shaders (seconde branche `uHasMask`, `uMask`, `suck`, `GLASS_GLSL`) : laissé, faute de pouvoir
  comparer l'image au pixel près (fond aléatoire) ; à retirer avec une capture de référence figée.

  le goulot est le GPU ; gain faible.
- `srcset` des vignettes, dimensions des images : CLS déjà quasi nul à l'accueil (0,001) ; à faire avec de nouvelles
  tailles d'images générées.
- Découpage plus poussé de `main.js` (fiches, pistes, accueil) : possible, même méthode que l'étape 3.
